# 生成数据库规范

1. 读本 skill 目录往上两级的 `shared/workflow.md`（即插件根目录下的 `shared/workflow.md`），按其中的步骤执行。
2. 读本 skill 的 `references/defaults.md`。
3. 输出 `docs/standards/database.md`：
   - 标题写成 `# 数据库设计规范（<数据库> + <ORM 或数据访问库> + <迁移工具>）`，例如 `# 数据库设计规范（MySQL 8 + MyBatis-Plus + Flyway）`。
   - 开头写一句："凡是标"必须"或"禁止"的条目，代码评审时一律按硬性规则执行。"
   - 章节顺序：1. 命名　2. 主键　3. 通用字段　4. 字段类型　5. 注释　6. 字段顺序　7. 约束与索引　8. 查询　9. 迁移　10. 环境与库名　11. 种子数据　12. 备份与恢复。
   - 项目没有预置数据需求时，第 11 章保留规则、清单表留空；备份时间和保留份数直接用默认值；备份存放位置和部署方式属于第 2 类问题，用户没给时写占位并在汇报里列出。
4. 已有表的项目，第 1 章的业务域前缀表按现有表名整理；现有表名不统一时列出来问用户以哪种为准，并说明已有表不改名、只约束新表。
