# 生成技术选型规范

1. 读本 skill 目录往上两级的 `shared/workflow.md`（即插件根目录下的 `shared/workflow.md`），按其中的步骤执行。第 2 步识别出的技术就是本文的主要内容。
2. 读本 skill 的 `references/defaults.md`。
3. 输出 `docs/standards/tech-stack.md`：
   - 标题写成 `# 技术选型规范`。
   - 章节固定为：1. 选型总表　2. 引入与升级依赖　3. 选择依据。
   - 项目没有前端时删掉选型总表里的前端各行，没有数据库时删掉数据库各行。
4. 版本号只写在本文：其他规范的标题和正文只写技术名，需要版本时写"版本见技术选型规范"。本文写完后检查 `docs/standards/` 下其他已有规范，正文里出现版本号的列给用户，确认后改成引用本文。
5. 每一行的"依据"写出确定这一行的文件（例如 `backend/pom.xml`、`frontend/pnpm-lock.yaml`）；空项目写"用户指定"或"推荐值"，推荐值同时列进汇报的"使用的推荐值"一节。
