# CLAUDE.md 模板

CLAUDE.md 每次对话都会被加载，所以只写 AI 每次都需要知道的内容：引用规范、目录、硬性约定、命令。详细规则留在规范文件里，用 `@` 引用，不复制进来。尖括号里的内容按项目填写，没有内容的小节删掉。

````markdown
# <项目名>

<一句话说明项目是什么。有设计文档的写出位置，例如：完整设计见 `docs/design.md`。>

## 规范（写代码前必读，与之冲突时以规范为准）

- 技术选型：@docs/standards/tech-stack.md
- 开发流程（分支、提交说明、合并请求）：@docs/standards/workflow.md
- 后端：@docs/standards/backend.md
- 数据库：@docs/standards/database.md
- 前端：@docs/standards/frontend.md
- UI 设计：@docs/standards/<design.md，沿用已有 ui.md 时写 ui.md>
- 开发者上手：`docs/standards/README.md`（给人看的环境和流程说明，不需要每次加载）

## 目录

| 目录 | 内容 |
|---|---|
| `<backend/>` | <后端，框架名> |
| `<frontend/>` | <前端，框架名> |
| `docs/` | <设计文档、规范> |

## 根目录规则

除非是必要文件，否则禁止在项目根目录新增文件。根目录只允许存放：
- 上表列出的目录
- <根目录现有的必要文件，例如 `CLAUDE.md`、`README.md`、`CHANGELOG.md`、`.gitignore`、`docker-compose.yml`、`.env.example`>

脚本、临时文件、测试输出、笔记、各子项目的配置文件一律放到对应子目录，临时文件放系统临时目录。确实需要在根目录新增文件时，先说明理由，经用户同意后再加进上面的清单。

## 工作约定

- 不确定的地方先问用户或者查资料，不要猜；需要外部资料支撑的结论，要有源码或官方文档作为依据。
- 提交说明、分支和合并按开发流程规范执行。
- 改动完成后先跑通对应子项目的质量门禁，再提交。
- 引入新的运行时依赖前，先登记到技术选型规范。
- 为验证而启动的开发服务，任务结束前关掉。
- 改表结构或写 SQL 之前，先读迁移文件或模型代码里的真实表结构，不按猜测的字段名写。
- 删库、清空表、执行恢复这类操作，先核对库名和环境、做一次备份，并得到用户明确同意。
- 只在用户明确要求时部署，部署前先读部署文档。
- <项目特有的硬性约定，例如"生成文件 `src/types/api.gen.ts` 不手改，改接口后执行 `pnpm gen:api`">

## 常用命令

在 `<backend/>` 目录执行：
- 安装依赖：`<命令>`
- 启动服务：`<命令>`
- 执行迁移：`<命令>`
- 质量门禁：`<命令>`

在 `<frontend/>` 目录执行：
- 安装依赖：`<命令>`
- 启动开发服务：`<命令>`（<访问地址>）
- 质量门禁：`<命令>`
````

填写要求：
- "根目录规则"的允许清单按根目录里实际存在的必要文件写。
- "工作约定"的前八条是默认约定，用户不同意的删掉；项目没有数据库时删掉第六、七条，没有部署文档时第八条改为"只在用户明确要求时部署"；没有生成开发流程规范时，第二条改成写出提交说明格式（看 `git log`，没有统一格式时用 `<type>: <中文描述>`）；没有技术选型规范时删掉第四条。项目特有约定从规范和 README 里提取，只放 AI 最容易违反的几条。
- 只生成了部分规范时，"规范"一节只列已有的文件。
- CLAUDE.md 本身不超过 200 行（`@` 引用的文件不计入行数，但它们同样在启动时加载，不能用 `@` 引用来节省上下文）。
- 每条约定都写成能检查的形式：写"提交前在 `backend/` 执行 `<门禁命令>`"，**禁止**写"注意代码质量""测试改动"这类无法判断是否做到的话。
- 逐行检查"删掉这一行，AI 会不会因此出错"，不会就删。**禁止**写读代码就能知道的内容、语言的通用惯例、逐个文件的说明；"目录"一节只写到目录这一级。
- "重要""必须"之类的强调只加在 AI 反复违反的个别条目上，**禁止**每条都加。
- 给维护者看、不需要 AI 读的备注写成块级 HTML 注释 `<!-- ... -->`，它不会被加载进上下文。
- 每次都必须执行、不允许例外的动作（例如每次改完都跑格式化），在汇报里建议改用 Claude Code 的 hook，不写进 CLAUDE.md。
- 写完后检查 CLAUDE.md 和项目里其他 AI 说明文件（`AGENTS.md`、`.claude/rules/*.md`、`CLAUDE.local.md`）没有互相矛盾的规定，有矛盾的列给用户确认。
- 用户需要个人偏好设置时，放进根目录的 `CLAUDE.local.md`，同时把它加入 `.gitignore` 和"根目录规则"的允许清单。
