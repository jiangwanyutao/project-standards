# 生成 UI 设计规范骨架

1. 读本 skill 目录往上两级的 `shared/workflow.md`（即插件根目录下的 `shared/workflow.md`），按其中的步骤执行。
2. 读本 skill 的 `references/defaults.md`。
3. 找到目标项目的主题文件：CSS 变量文件（`globals.css`、`variables.scss`）、Tailwind 的 `@theme` 或 `tailwind.config.*`、组件库主题配置（Element Plus 的 `--el-*` 变量、Ant Design 的 `ConfigProvider theme`）。已有取值的按已有取值填写，没有的写 `<待补充>`；规范里每个变量都写出它所在的文件。
4. 主题切换（浅色、深色、跟随系统）和响应式是必须有的，直接写进规范，不询问用户。界面类型（后台管理、面向用户的站点、移动端）属于第 1 类问题，推荐值是"后台管理"；不是后台管理时，第 4 章按实际界面类型改写，并在汇报里说明。
5. 输出 `docs/standards/ui.md`，章节为：1. 原则　2. 主题与设计变量　3. 状态色　4. 布局。开头写明："本文的变量全部定义在 <主题文件>，**禁止**在组件里写死颜色值或像素值。标 `<待补充>` 的取值由团队后续补充。技术约束以前端规范为准。"
6. 汇报里单独写一项"需要用户补充的取值"：列出所有 `<待补充>` 的变量（主题色、状态色、字体、字号、间距、圆角、阴影、布局尺寸）。用户给了品牌色的，写明已填入主色，以及它和主色上文字的对比度是否达到 4.5:1。
