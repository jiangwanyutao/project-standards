# UI 设计规范默认规则

`design.md` 分四部分：视觉风格、控件组件规格、页面结构、页面逻辑。

- 空项目只生成骨架：章节结构、主题切换机制、变量名、组件清单、页面模板和通用交互规则。颜色、字号、间距、尺寸等具体取值，以及页面清单、菜单分组，都写成占位 `<待补充>`，由用户后续补充；用户在请求里给了取值的（例如品牌色），填进对应位置。
- 有代码时按代码填写：变量取主题文件里已有的取值，组件取组件目录里已有的组件和变体，页面取路由表里已有的页面。代码和本文默认规则不一致的地方，在汇报里列出来问用户以哪个为准。

## 1. 视觉风格

### 1.1 原则（与技术无关，原样写入，示例换成目标项目的业务）

1. **用间距分组**：相关的元素靠近，不相关的元素拉开距离。能用间距分组的，就不用分割线或边框。
2. **一致**：外观相同的元素，行为也必须相同；行为不同的元素，外观要能区分开。
3. **层级清晰**：每个页面只有一个主操作（主按钮样式），其他操作用次要、幽灵或链接样式。
4. **去掉多余样式**：不堆叠边框、阴影、渐变，一个区域最多用一种区分手段。
5. **颜色要有目的**：彩色只用于状态和主操作，不用来装饰。
6. **对比度**：界面元素（边框、图标、控件）与背景的对比度不低于 3:1；正文（18px 及以下）不低于 4.5:1。补充颜色取值时按这条检查。
7. **不能只靠颜色传达信息**：状态必须同时有颜色和文字（或图标），例如优先级标签写成"P0 紧急"，不能只显示一个红点。
8. **字体**：全站只用一种无衬线字体，字重只用 400（正文）、500（导航、按钮、标签）、600（标题、强调数字）三档。
9. **少用全大写**：中文界面里，英文缩写之外不使用全大写。
10. **不用纯黑文字**：正文用前景色变量。
11. **文字左对齐**：正文和表格文字左对齐，ID 列也左对齐；数量、金额、耗时这类数字列右对齐。
12. **行高**：正文行高不低于 1.5。

### 1.2 主题切换（必须有，不询问用户）

- 提供浅色、深色、跟随系统三种模式，默认跟随系统；用户的选择存在浏览器本地，下次打开沿用。
- 写明切换入口的位置（例如用户菜单或顶栏）和实现方式：在根元素上切换主题标记（例如 `<html class="dark">`），所有颜色都通过变量取值，切换主题只改变量。
- **禁止**：组件里写死颜色值、像素字号；需要新颜色时先在主题文件里加变量。

按技术确定：React 写出主题 Provider 所在的文件；Vue 写出切换主题的 composable 所在的文件；Element Plus 写明切换时同时切换 `html.dark`。

### 1.3 颜色变量

用表格写"类别 | 变量名 | 浅色 | 深色"，变量名用目标项目真实的变量名，没有取值的写 `<待补充>`：

| 类别 | 默认变量名（shadcn 体系） | 浅色 | 深色 |
|---|---|---|---|
| 主色 / 主色上的文字 | `--primary` / `--primary-foreground` | `<待补充>` | `<待补充>` |
| 页面背景 / 正文 | `--background` / `--foreground` | `<待补充>` | `<待补充>` |
| 弱化底色 / 次要文字 | `--muted` / `--muted-foreground` | `<待补充>` | `<待补充>` |
| 卡片和弹出层 | `--card` / `--popover` | `<待补充>` | `<待补充>` |
| 悬停底色 | `--accent` | `<待补充>` | `<待补充>` |
| 边框 / 输入框边框 | `--border` / `--input` | `<待补充>` | `<待补充>` |
| 焦点环 | `--ring` | `<待补充>` | `<待补充>` |

用户给了品牌色时：主色一行填品牌色；检查它和主色上文字的对比度，不到 4.5:1 时在表格下面写明，主色上文字的取值留给用户决定，不自行改色。

按技术确定：shadcn/ui 写在 `globals.css` 的 `:root`（浅色）和 `.dark`（深色）；Element Plus 覆盖 `--el-color-primary`、`--el-bg-color`、`--el-text-color-primary`、`--el-border-color` 等，深色用 `html.dark` 加 `element-plus/theme-chalk/dark/css-vars.css`；Ant Design 写进 `ConfigProvider` 的 `theme.token`，深色用 `theme.darkAlgorithm`。组件库变量名不同的，表格里同时写出语义（例如"主色"）和组件库的变量名。

### 1.4 状态色

状态标签组件只能读下列语义变量，**禁止**在页面里写颜色：

| 语义 | 变量 | 用于 | 浅色 | 深色 |
|---|---|---|---|---|
| 成功 | `--success` | 通过、已完成 | `<待补充>` | `<待补充>` |
| 警告 | `--warning` | 待处理、即将到期 | `<待补充>` | `<待补充>` |
| 错误 | `--destructive` | 失败、异常 | `<待补充>` | `<待补充>` |
| 信息 | `--info` | 进行中 | `<待补充>` | `<待补充>` |
| 禁用或无 | `--muted-foreground` | 忽略、未开始 | 同 1.3 节 | 同 1.3 节 |

"用于"一列按目标项目的业务状态改写。组件库自带状态色（Element Plus 的 success/warning/danger/info）时，直接写组件库的对应变量，不另建一套。

### 1.5 字体、字号、间距、圆角、阴影

用表格写"类别 | 变量名或档位 | 取值 | 用于"，变量写出所在的文件：

| 类别 | 变量名或档位 | 取值 | 用于 |
|---|---|---|---|
| 字体 | `--font-sans` | `<待补充>` | 全站 |
| 字号 | 正文、辅助文字、小标题、页面标题各一档 | `<待补充>` | 按档位名写 |
| 间距 | 基础单位和常用倍数 | `<待补充>` | 组件内边距、区块间距 |
| 圆角 | `--radius` | `<待补充>` | 按钮、输入框、卡片 |
| 阴影 | 弹出层一档 | `<待补充>` | 下拉菜单、弹窗 |

- **禁止**：使用表外的字号、间距、圆角；需要新档位时先在主题文件里加。

### 1.6 图标

- 图标只用一个图标库（库名见前端规范）。
- 图标和相邻文字同高，颜色跟随文字颜色。
- **必须**：只有图标没有文字的按钮，加 `aria-label` 和悬停提示。

## 2. 控件组件规格

### 2.1 所有控件的状态外观

| 状态 | 外观 |
|---|---|
| 默认 | 读颜色变量，不加多余装饰 |
| 悬停 | 底色换成 `--accent`；**禁止**和选中状态看起来一样 |
| 键盘焦点 | 显示 `--ring` 焦点环；**禁止**去掉焦点环 |
| 选中 | 用主色或加粗等和悬停明显不同的方式 |
| 禁用 | 降低不透明度、鼠标显示禁止图标，没有悬停效果 |
| 报错 | 边框用 `--destructive`，错误文字写在控件下方 |
| 加载中 | 按钮显示加载图标并禁用，防止重复提交 |

### 2.2 组件清单

用表格写"组件 | 源码位置 | 用途 | 变体 | 尺寸 | 使用约束"。有代码时按组件目录里真实存在的组件写，变体和尺寸取组件源码里定义的取值（例如 shadcn 组件 `cva` 里的 `variant`、`size`）；空项目按下表写，位置按前端规范的目录，尺寸写 `<待补充>`：

| 组件 | 用途 | 变体 | 使用约束 |
|---|---|---|---|
| 按钮 Button | 触发操作 | 主要、次要、幽灵、链接、危险 | 一个区域只有一个主要按钮；删除等不可撤销操作用危险变体 |
| 输入框 Input、多行输入 Textarea | 输入文字 | — | 标签放在输入框上方；占位文字只写示例，不代替标签 |
| 下拉选择 Select | 从固定选项里选一个 | 单选、可搜索 | 选项不超过 5 个时改用单选按钮组 |
| 勾选 Checkbox、开关 Switch | 布尔值 | — | 开关只用于立即生效的设置；需要点保存的表单用勾选框 |
| 表格 Table | 展示列表数据 | — | 宽表格在表格容器内横向滚动；行内操作不超过 3 个，多的收进"更多"菜单 |
| 弹窗 Dialog | 不离开当前页完成的短任务 | — | 字段超过 6 个的表单改用单独页面 |
| 确认框 ConfirmDialog | 不可撤销操作前确认 | 普通、危险 | 写明操作对象的名称和后果，确认按钮写动作名（例如"删除"），不写"确定" |
| 消息提示 Toast | 操作结果和接口错误 | 成功、错误 | 表单字段的错误写在字段下方，不用 Toast |
| 状态标签 StatusBadge | 显示业务状态 | 按 1.4 节的语义 | 只读状态色变量；同时显示文字 |
| 页签 Tabs | 同一对象的不同视图切换 | — | 只切换同一对象的视图，不相关的内容拆成不同页面 |
| 分页 Pagination | 列表翻页 | — | 显示总条数；切换每页条数后回到第 1 页 |
| 页面标题 PageHeader | 页面标题和主操作 | — | 每个页面都用它，不自己拼标题行 |
| 空状态 EmptyState、加载 LoadingState、错误 ErrorState | 列表和详情的三种状态 | — | 见第 4 章 |

组件库自带的组件（Element Plus 的 `ElButton` 等）写组件库的组件名和变体名，不另行封装。

## 3. 页面结构

### 3.1 整体框架（后台管理类界面）

- 左侧导航、顶栏、右侧内容区。顶栏放面包屑、主题切换和用户菜单。侧栏宽度、收起后宽度、顶栏高度、内容区内边距写成变量，取值 `<待补充>`。
- **响应式**（必须有，不询问用户）：页面在 1280px 以上的宽屏和 1024px 以下的窄屏都能正常使用；窄屏时导航收起为按钮 + 抽屉；**禁止**页面出现横向滚动（宽表格在表格容器内横向滚动）。
- 写出外壳组件的位置（例如 `components/app/AppLayout`、`components/app/Sidebar`）。

### 3.2 路由与菜单

- 写出路由表所在的文件。
- 用表格写"菜单分组 | 页面 | 路由 | 页面模板 | 源码位置"。有代码时按路由表和菜单配置写；空项目按业务域列出菜单分组，页面写 `<待补充>`。

### 3.3 页面模板

- **列表页**：自上而下依次是标题行（标题 + 主操作）、筛选栏、数据表格、分页。
- **详情页**：顶部是标题和操作按钮，左上角是返回链接；主要内容和基本信息分区展示。
- **表单页**：标签放在输入框上方；必填项在标签后加 `*`；错误提示在字段下方，用错误色；提交和取消按钮放在表单底部，提交按钮在前。

有代码时每个页面归到一种模板；不属于这三种的页面（例如看板、画布）单独写出它的区块组成。

按技术确定：界面类型是面向用户的站点或移动端时，按实际界面类型改写本章的整体框架、响应式要求和页面模板。

## 4. 页面逻辑

### 4.1 通用交互规则

- **加载、空状态、错误**：每个列表和详情都必须有这三种状态，分别用 2.2 节的统一组件。空状态区分"还没有数据"（给出新建入口）和"筛选后没有结果"（给出清空筛选的入口）。错误状态显示错误信息和重试按钮。
- **筛选与分页**：筛选条件和页码写进 URL 查询参数，刷新和分享链接后保持；修改筛选条件后回到第 1 页。
- **表单提交**：提交时先做前端校验，错误显示在字段下方并把焦点移到第一个错误字段；提交中按钮显示加载并禁用；后端返回的字段错误显示到对应字段；成功后用 Toast 提示，再返回列表或详情。
- **离开未保存的表单**：表单有改动时离开页面，弹确认框提示改动会丢失。
- **不可撤销操作**：删除、作废等操作先弹确认框，见 2.2 节。
- **权限**：没有权限的菜单和按钮不显示；有权限但当前状态不允许的操作显示为禁用，悬停提示原因。直接访问没有权限的页面时显示无权限页面；页面不存在时显示 404 页面。
- **接口错误**：统一用 Toast 显示后端返回的提示信息（实现见前端规范请求层）；登录过期时跳转登录页，登录后回到原页面。

### 4.2 各页面逻辑

用表格写"页面 | 数据来源（接口） | 主要交互 | 权限 | 特殊状态"。有代码时按页面源码和请求函数写；空项目写一行 `<待补充>` 示例。

带状态流转的业务对象（例如订单、工单），用 mermaid 状态图写出状态和触发每次流转的操作；空项目写 `<待补充>`。
